# KAIST 학교생활 에이전트 설계 문서 (v0.2)

작성일: 2026-10-13 (v0.1) / 개정: 2026-10-14 (v0.2)
상태: 기술 검증 완료(`docs/phase0-report.md`), 구현 진행 중

v0.2 변경 요약: 0단계 검증 결과를 반영했다.
- 수집 방식을 "쿠키 + sesskey AJAX + HTML 파싱"으로 확정하고, WS 토큰은 쓰지 않는다.
- 인증 흐름을 쿠키 파일 중심으로 바꾸고 persistent profile을 없앴다.
- 저장 위치를 확정했다.
- 가정 표에 A8, A9를 추가하고 위험 요소를 보강했다.
- CLI 이름과 폴더 규칙을 확정했다.

---

## 1. 한 줄 요약

- 개인 Windows PC에서 도는 TypeScript CLI `kaist`가 KLMS의 과제, 공지, 강의자료를 수집한다. 수집한 내용은 구글 드라이브 폴더와 전용 구글 캘린더에 정리한다.
- Claude Code는 이 CLI를 도구로 써서 학교생활을 논의한다.
- 로그인은 자동화할 수 없다. 세션이 만료됐을 때 비밀번호 직접 입력과 폰 승인을 1회 받는다.

## 2. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 본체 기기 | 개인 Windows PC | 브라우저 자동화와 파일 저장이 가능한 유일한 환경 |
| 에이전트 | Claude Code가 CLI를 호출 (Codex 등도 같은 CLI 사용 가능) | 별도 에이전트 런타임을 만들 필요 없음 |
| 언어 | TypeScript (Node.js) | Playwright 원본 플랫폼, 타입으로 깨진 곳 추적, Windows 설치 단순 |
| CLI 이름 | `kaist` | 짧고, 2차에 Portal 등을 붙여도 이름이 맞음 |
| 인증 | 브라우저를 띄워 SSO 로그인, 폰에서 숫자 매칭 승인 1회 | 숫자 매칭 방식은 무인 로그인 불가 |
| 비밀번호 | 사용자가 매번 직접 입력. CLI는 저장·자동 입력하지 않고 브라우저 자동완성도 쓰지 않음 | 정보보안지침 제75조①7호(자동 비밀번호 입력 금지) |
| 수집 방식 | 쿠키 + sesskey AJAX(`/lib/ajax/service.php`) + HTML 파싱. Playwright는 로그인 전용 | 0단계 V3, V7. 마감은 AJAX 캘린더에서 유닉스 초로 얻음 |
| WS 토큰 | **쓰지 않는다.** `launch.php`, `webservice/rest`, `tool_mobile_*` 호출 코드를 넣지 않고, 옵션으로도 두지 않는다 | 수명 미상, 사용자가 폐기 불가(보안 키 페이지 없음). V7에서 없이도 충분함을 확인 |
| 동작 방식 | 대화형. 세션이 살아 있으면 재사용하고, 만료되면 로그인 1회 후 전부 몰아서 수집 | 세션 유지 시간이 불규칙해 백그라운드 자동 수집은 신뢰 불가 |
| 승인 횟수 줄이기 | 1차에서는 하지 않음. 세션 유지용 주기적 요청, SSO 쿠키 저장·재주입 모두 구현하지 않음 | 백그라운드 동작 배제 원칙 |
| 수집 대상 과목 | 이번 학기 수강 과목 전체 자동 인식 | 수강 과목 목록 AJAX + 학기 필터 (V4-b, A4) |
| 수집 범위 | 문서 파일 전부, 공지/게시판 글, 과제 설명·마감·제출 상태, 주차 구성 | 이후 작업에서 재로그인을 피하기 위해 최대한 수집 |
| 강의 영상 | 받지 않음. 제목, KLMS 링크만 목록으로 저장 | Panopto 스트리밍(LTI). 용량과 우회 문제가 있고 에이전트가 읽지 못함 |
| 다운로드 막힌 자료 | 우회하지 않음. "뷰어 전용"으로 목록에만 기록 | 교수의 저작권 보호 설정 존중 |
| 캘린더 | "KLMS" 전용 구글 캘린더에 마감 자동 등록 | 개인 일정과 분리하고, 실수해도 전용 캘린더만 비우면 됨 |
| 캘린더 정돈/계획 | CLI는 조회/추가/수정/삭제 명령만 제공, 나머지는 대화로 처리 | |
| 모바일 | 동기화된 캘린더와 드라이브 보기, 드라이브 자료로 논의 | 원격으로 PC를 부리는 기능은 만들지 않음 |
| 실행 환경 | 개인 Windows PC만. 서버, 백그라운드 실행 없음 | Cloudflare, 공기계 서버 방식은 검토 후 채택하지 않음 |

## 3. 범위

### 1차 (이 문서의 대상)
- KAIST SSO 로그인 및 세션 관리
- KLMS 읽기: 과목, 주차 구성, 과제, 퀴즈, 공지, 강의자료, 영상 링크
- 강의자료 다운로드와 과목별 폴더 정리
- 구글 캘린더 전용 캘린더에 마감 등록, 캘린더 기본 명령
- Claude Code용 안내 파일(CLAUDE.md)

### 2차 (1차가 안정된 뒤, 사용자가 요청할 때. 새 설계 문서를 먼저 씀)
- Dooray 메일 읽기 (IMAP 불가 확인: 2021 전환 때 중지, 공공기관 Dooray 미제공 → Gmail 전달 방식, `docs/mail-design.md`)
- Gmail 읽기 (기존 도구 활용, 새로 만들지 않음)
- 메일 초안 작성 후 승인받아 발송

### 3차 이후 (필요가 확인되면)
- Portal, 기숙사 사이트 조회 (SSO 모듈 재사용)
- 카카오톡: 대화 내보내기 파일 파싱 정도의 읽기 전용부터 검토
- KLMS 과제 제출 (실패하면 성적에 직결되므로 별도 설계)

### 만들지 않는 것
- 수강신청, 기숙사 신청 등 경쟁성 신청 행위의 자동화 (매크로 금지 규정 위험)
- 2단계 인증 우회, 비밀번호 저장·자동 입력
- 스트리밍 영상 추출
- WS 토큰 사용
- 수집 자료의 공유·재배포 기능

## 4. 구조

```
[Claude Code] ── 명령 실행 ──> [kaist CLI]
                                  │
        ┌─────────────────────────┼───────────────────────────────┐
        │                         │                               │
   [sso 모듈]                [klms 모듈]                       [cal 모듈]
   Playwright 새 컨텍스트로   ├ http: 쿠키, UA, 간격, 동시≤2,     Google Calendar API
   로그인 창 띄우고 대기,     │       만료 감지 통합               (OAuth, 전용 캘린더만)
   완료 판별 후 쿠키 추출     ├ ajax: sesskey + service.php
   (KLMS와 분리)              │   (과목 목록, 캘린더, 변경 감지)
                              └ adapters: HTML 파서
                                  (과목 페이지, 과제, courseboard,
                                   셀렉터는 한 파일에 모음)
        │                         │                               │
   [로컬 상태 저장소]         [드라이브 동기화 폴더]           [구글 캘린더 "KLMS"]
   %LOCALAPPDATA%\kaist-cli   강의자료, 요약 md
   쿠키, OAuth 토큰, DB,      (모바일에서 열람)
   HTML 원문 보관본
```

핵심 원칙:
- **SSO 모듈은 KLMS와 분리한다.** 이후 Portal 등을 붙일 때 그대로 재사용한다.
- **사이트별 코드는 얇은 어댑터로 둔다.** 셀렉터를 한 파일에 모아 페이지 개편 시 고칠 범위를 좁힌다.
- **모든 조회 명령은 `--json` 출력을 지원한다.** 에이전트가 결과를 안정적으로 읽기 위함이다.
- **로컬에 저장된 데이터만으로 논의가 가능해야 한다.** 조회 명령은 로컬 데이터를 읽고, `sync`와 `login`만 KLMS에 접속한다.
- **파싱에 실패하면 조용히 넘어가지 않는다.** 무엇이 어디서 깨졌는지 명확한 오류를 낸다.
- **읽기 전용.** 제출, 글쓰기, 설정 변경 등 상태를 바꾸는 요청은 코드에 없다.

### 정보별 수집 소스 (0단계 보고서 3.1)

| 정보 | 소스 | 비고 |
|---|---|---|
| 수강 과목·학기 | AJAX `core_course_get_enrolled_courses_by_timeline_classification` | `shortname` 접미사(`_2026_3`), `startdate/enddate`, `coursecategory`로 필터. 0건이면 실패 |
| 주차 구성·모듈 목록 | `course/view.php?id=X&section=0` HTML | `section=0`이 "모두" 보기. 파라미터 없이 열면 현재 주차 근처만 나옴 |
| 모듈 변경 감지 | AJAX `core_course_get_updates_since` | 재파싱 범위를 줄이는 보조 신호 |
| 강의자료 파일 | HTML `downloadFile('…/pluginfile.php/…')` → 쿠키로 다운로드 | HEAD로 `ETag`/`Last-Modified`/`Content-Length` 비교 |
| 과제 마감 (값) | AJAX `core_calendar_get_calendar_monthly_view` | `eventtype=due`, 유닉스 초. **이벤트 `instance`는 cmid** (KLMS 특이) |
| 과제 마감 (교차검증) | 과목 페이지 `strong.end-dt`, 과제 페이지 "마감 일시" | 검증에만 사용 |
| 과제 설명·첨부·제출 상태 | `mod/assign/view.php?id=<cmid>` HTML | `#intro`, introattachment, `.submissionstatustable` |
| 퀴즈 | 캘린더 open/close 이벤트 + `mod/quiz/view.php` HTML | 미검증 |
| 공지·게시판 | `mod/courseboard/view.php`, `article.php` HTML | KLMS 전용 모듈, API 없음. 글 ID `bwid`, 수정 시각 없음 |
| 영상 | 과목 페이지의 lti 모듈 | 제목·cmid·링크만 |

## 5. 인증 흐름

1. `kaist sync`(또는 `login`)를 실행하면 쿠키 파일(`%LOCALAPPDATA%\kaist-cli\session.json`)을 읽는다.
2. 세션 프로브 `GET /my/`(리다이렉트 따라가지 않음)로 상태를 판별한다.
   - 200이고 `sesskey`가 있으면 유효 → 브라우저 없이 바로 수집한다. sesskey는 메모리에만 둔다.
   - 3xx이고 Location이 `/login/index.php` 또는 `ssologin.php`이면 만료다.
3. 만료됐으면 Playwright가 **새 브라우저 컨텍스트**(persistent profile 없음)로 창을 띄우고 `login/ssologin.php`로 이동한다.
4. 사용자가 아이디·비밀번호를 직접 입력하고 폰에서 숫자 매칭을 승인한다.
5. CLI가 로그인 완료를 판별한다. SSO 중간 URL은 신호로 쓰지 않고, 다음 세 조건이 모두 참이면 완료로 본다.
   - host가 `klms.kaist.ac.kr`이고 `/login/` 아래가 아님
   - `window.M.cfg.sesskey`가 문자열
   - body에 `notloggedin` 클래스 없음
6. `klms.kaist.ac.kr` 쿠키를 전부 저장한다(로드밸런서 쿠키 `9-rr`/`12-rr` 포함).
7. 브라우저를 닫기 전에 Node fetch로 프로브를 한 번 통과시켜 확인한 뒤 종료한다. 사용자가 창을 닫으면 "로그인 취소"로 끝낸다.
8. 수집 도중 세션이 끊기면 받은 데까지 저장하고, 어디서 끊겼는지 알린 뒤 재로그인을 요청한다.

**만료 판별 함수** (모든 요청이 거침):
- 페이지/파일 GET: 3xx이고 로그인 경로로 가거나, 파일을 기대했는데 `text/html`이 오면 만료
- AJAX: `servicerequireslogin`이면 만료. `invalidsesskey`이면 sesskey를 다시 얻어 1회 재시도
- AJAX `servicenotavailable`: 허용되지 않는 함수다. 코드 오류로 즉시 실패
- AJAX `accessexception`: 권한 문제다. 해당 항목만 건너뜀

관찰된 사실 (0단계 V2):
- 쿠키는 전부 세션 쿠키다. 브라우저를 다시 열면 사라지므로 브라우저 프로필로는 세션을 보존할 수 없다.
- 쿠키 파일로는 재사용된다. [추정] 서버 유휴 만료는 3시간(`sessiontimeout=10800`)이다.
- "매번 승인이 필요할 수 있다"를 기본 전제로 한다.

## 6. 명령 설계 (초안)

```
kaist login                     로그인만 수행 (세션 확인/갱신)
kaist status                    세션 상태, 마지막 수집 시각, 과목 수

kaist sync                      전체 증분 수집 + 파일 다운로드 + 캘린더 반영
kaist sync --course <과목>      특정 과목만
kaist sync --no-calendar        캘린더 반영 생략
kaist doctor [<과목>]           불변식 검사 (파서 고장, KLMS 개편 감지)

kaist courses                   수강 과목 목록
kaist assignments [--due 7d]    과제/퀴즈 목록 (로컬 데이터, needs_review 표시)
kaist notices [--since 3d]      공지/게시판 글
kaist files [--new]             강의자료 목록, 새로 받은 것만 보기
kaist videos                    영상 링크 목록

kaist cal list [--from --to]    전용 캘린더 일정 조회
kaist cal add / update / delete 일정 추가, 수정, 삭제
kaist cal push                  로컬 마감 데이터를 캘린더에 반영
```

- `kaist cal` 쓰기 명령은 기본적으로 "KLMS" 전용 캘린더에만 동작한다. 다른 캘린더를 건드리려면 명시적 옵션이 필요하다.
- sync 결과에는 "새로 생긴 것, 바뀐 것", `needs_review` 과제, 처리하지 못한 활동 유형과 개수를 출력한다.

## 7. 데이터 저장

### 드라이브 동기화 폴더 (모바일에서 보임)

- 기본 루트는 `G:\내 드라이브\KAIST\`(Google Drive for desktop)이고 설정으로 바꿀 수 있다.
- 과목 폴더 이름은 `<과목코드> <과목명>`이다.
  - 과목코드는 `shortname`에서 학기 접미사(`_2026_3`)를 뗀 것이다. 예: `MAS.20050(B) 확률및통계`
  - Windows에서 쓸 수 없는 문자(`\ / : * ? " < > |`)는 `_`로 바꾼다.

```
<드라이브>/KAIST/2026-가을/
  _요약.md                      전 과목 마감, 최근 공지, 새 자료 요약 (sync마다 갱신)
  <과목코드> <과목명>/
    _과목정보.md                과제 목록, 공지 본문, 영상 링크
    강의자료/                   주차별 원본 파일
    과제/<과제명>/              과제 설명문(md), 첨부파일
```

- `_요약.md` 맨 위와 캘린더 이벤트 설명에는 마지막 수집 시각을 표시한다. PC에서 수집을 시켜야만 갱신되는 구조라서, 모바일에서 볼 때 정보가 얼마나 오래됐는지 알 수 있어야 한다.
- `_요약.md`와 `_과목정보.md`는 모바일의 Claude 앱이 드라이브에서 읽고 논의하기 위한 파일이다.

### 로컬 상태 저장소 (`%LOCALAPPDATA%\kaist-cli\`, 드라이브·OneDrive 밖)
- 세션 쿠키 파일 (`session.json`)
- 구글 OAuth 토큰
- 수집 기록 DB (SQLite): 항목별 KLMS ID(cmid, bwid), 내용 해시, ETag, 받은 파일 경로, 캘린더 이벤트 ID
- HTML 원문 보관본 (최근 1회분, 파서 고장 재현용)

**세션 쿠키와 토큰은 절대 드라이브 폴더나 OneDrive에 두지 않는다.** 유출되면 계정이 그대로 열린다. 프로젝트 폴더가 OneDrive 안에 있으므로 저장소 안에도 두지 않는다.

## 8. 증분 수집

- 각 항목을 KLMS 고유 ID로 식별한다.
  - 활동: cmid
  - 게시글: `bwid`
  - 파일: cmid + 파일 URL
- 변경 판단 기준:
  - 파일: HEAD의 `ETag`/`Last-Modified`/`Content-Length`
  - 과제: 캘린더 마감과 과제 페이지 내용 해시
  - 게시글: 본문 해시 (게시판에는 수정 시각이 없음)
  - `core_course_get_updates_since`로 바뀐 모듈만 다시 파싱한다.
- 교수가 파일을 교체하면 이전 파일을 지우지 않고 새 버전을 따로 저장한다.
- sync가 끝나면 "새로 생긴 것, 바뀐 것" 목록을 출력한다. 에이전트는 이를 그대로 브리핑에 쓴다.

## 9. 캘린더 동기화

- 최초 실행 시 "KLMS" 캘린더를 생성한다.
- 과제/퀴즈 하나당 이벤트 하나. 이벤트의 비공개 속성에 cmid를 기록해 중복 등록을 막는다.
- 마감 값은 KLMS 캘린더의 유닉스 초만 쓴다. `needs_review` 과제는 등록하지 않는다.
- 마감이 바뀌면 기존 이벤트를 수정한다. 과제가 사라지면 삭제하지 않고 제목에 표시만 한다(오탐 대비).
- 이벤트 설명에 KLMS 원문 링크와 마지막 수집 시각을 넣는다.
- 사전 준비: 구글 클라우드 프로젝트에서 Calendar API를 켜고 데스크톱 앱용 OAuth 클라이언트를 직접 발급해야 한다(1회, 약 10분).
- S4 시작 시 정할 것: 이벤트 제목 규칙, 알림 시점, 시각 일정/종일 일정 여부.

## 10. 에이전트 연결

프로젝트 폴더의 CLAUDE.md에 다음을 적어둔다.
- 각 명령의 용도와 출력 형식
- "조회는 로컬 데이터로 답하고, 최신화가 필요하면 sync를 제안하고 사용자에게 폰 승인을 요청할 것"
- 드라이브 폴더 구조와 과제 풀이 논의 시 읽을 파일
- 캘린더 쓰기는 전용 캘린더에 한정, 삭제는 실행 전 확인

## 11. 가정과 검증 결과

| # | 가정 | 결과 (0단계) | 설계 반영 |
|---|---|---|---|
| A1 | KLMS는 Moodle 기반이고 로그인 후 일반 HTTP 요청으로 페이지를 읽을 수 있다 | **성립** (Moodle 3.9.1+) | 수집은 HTTP만으로 |
| A2 | Playwright 브라우저에서 SSO 로그인이 막히지 않는다 | **성립** (1회 시도) | 번들 Chromium 사용 |
| A3 | 로그인 후 쿠키를 저장해 두면 일정 시간 재사용된다 | **부분 성립**: 쿠키 파일로는 가능, 브라우저 프로필로는 불가. 유휴 만료 약 3시간 추정 | 쿠키 파일이 세션 저장소 |
| A4 | 수강 과목 목록과 학기 구분을 얻을 수 있다 | **성립** | AJAX + 학기 필터 |
| A5 | 강의자료는 직접 다운로드 가능한 링크로 제공된다 | **부분 성립**: 확인한 파일은 전부 가능. 뷰어 전용 자료는 미확인 | 뷰어 전용은 목록만 |
| A6 | 개인용 수집이 이용 규정에 저촉되지 않는다 | **확인 불가**: 명시 조항 없음. robots.txt `Disallow: /` | 낮은 빈도, 비공유, 수강 과목만 |
| A7 | Moodle 웹서비스 API(모바일 토큰)는 막혀 있다 | **불성립**: 열려 있음 | **사용하지 않음** (V7) |
| A8 | (신규) 과목 구성, 과제 설명·제출 상태, 공지는 HTML 파싱에 의존한다 | 사실 | 셀렉터 한 곳 집중, 불변식 검사, `doctor` |
| A9 | (신규) 캘린더 월별 뷰의 due 이벤트가 모든 과제를 포함한다 | 6/6 확인, 퀴즈 미검증 | 누락 시 HTML `end-dt`로 보충(`source=html`) |

## 12. 구현 순서

`docs/handoff-implementation.md` 4절(S0~S5)을 따른다. 한 세션에 한 단계씩 진행하고, 완료 기준을 확인한 뒤 사용자 승인을 받고 다음으로 간다.

- S0: 설계 문서 v0.2, CLAUDE.md
- S1: 인증과 과목 목록 (`login`, `status`, `courses`)
- S2: 과목 구성, 과제, 공지 수집 (`sync`, `assignments`, `notices`, `videos`, `doctor`)
- S3: 강의자료 다운로드와 폴더 정리 (`files`)
- S4: 구글 캘린더 (`cal`)
- S5: 에이전트 연결과 다듬기

## 13. 위험 요소

| 위험 | 가능성 | 대응 |
|---|---|---|
| KLMS 개편으로 HTML 파서가 깨짐 | 높음 (학기 단위로 발생 가능). 과목 구성, 과제, 공지가 모두 HTML 의존 | 셀렉터 한 파일 집중. 불변식 1~3: HTML cmid 집합 대조, 섹션·모듈 수와 링크 추출률, 테마 리비전 변화 감지. 실패 시 해당 과목 sync 중단과 명확한 오류. `doctor` 명령. HTML 원문 1회분 보관 |
| 마감 파싱·매핑 오류로 캘린더에 잘못된 시각 등록 | 중간 | 값은 캘린더 유닉스 초만 사용. HTML `end-dt`와 다르면 `needs_review`로 두고 등록 안 함. `instance`=cmid 매핑 검사. 이벤트 설명에 원문 링크. 초기 몇 주는 KLMS와 직접 대조 |
| 세션이 매우 짧아 매번 승인 필요 | 중간 | 감수. 승인 1회에 전부 수집하는 구조로 피해 최소화 |
| 학교가 자동화 접근을 차단 | 낮음~중간 | 요청 간격, 동시 2개 이하, 이번 학기 과목만. 차단 징후가 보이면 멈추고 사용자에게 알림 |
| 세션 쿠키 유출 | 낮음 | `%LOCALAPPDATA%\kaist-cli`에만 저장(드라이브·OneDrive 밖), PC 계정 잠금에 의존 |
| **0단계에서 발급된 WS 토큰** | 낮음 | 검증 중 모바일 토큰 1개가 서버에 발급됐다. 사용자가 폐기할 수 없다. **사용하지 않기로 결정**했고 재발급·재사용하지 않는다. 토큰 파일은 사용자 결정으로 `%LOCALAPPDATA%\kaist-cli\wstoken.txt`에 보관 중이다. 과거 OneDrive 동기화 사본은 OneDrive 휴지통 정리가 필요하다(사용자 할 일). 완전히 없애려면 KLMS 운영팀에 삭제 요청 |
| 범위 확장으로 유지보수 부담 증가 | 높음 | 1차가 한 학기 동안 안정적으로 쓰인 뒤에만 2차 착수 |

마감 시각 오류는 실제 피해로 이어지는 유일한 항목이다. 초기 몇 주는 캘린더만 믿지 말고 KLMS와 대조해야 한다.

## 14. 미결 사항

- (확정) CLI 이름: `kaist`
- (확정) 드라이브 폴더: `G:\내 드라이브\KAIST\`(설정 가능), 과목 폴더는 `<과목코드> <과목명>`
- (S4에서 결정) 캘린더 이벤트 형식: 제목 규칙, 알림 시점, 종일 일정 여부

## 15. 알려진 한계 (사용자가 받아들인 것)

- 새 과제를 자동으로 알려주지 않는다. PC에서 sync를 실행해야만 갱신된다.
- 로그인할 때마다 비밀번호 입력과 폰 승인이 필요하다.
- KLMS가 개편되면 HTML 파서가 깨질 수 있다. `doctor`와 불변식으로 감지하고 셀렉터 파일을 고친다.
- 초기 몇 주는 캘린더의 마감을 KLMS와 직접 대조해야 한다.
- 개인용 자동 수집을 허용하는 명시 규정은 없다(금지 조항도 없음). 낮은 빈도와 비공유 원칙으로 위험을 줄인다. 확실히 하려면 KLMS 헬프데스크에 문의할 수 있다.
