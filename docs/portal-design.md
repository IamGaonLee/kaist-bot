# S8 설계: KAIST Portal · ERP · 생활관 연결

작성: 2026-10-14
상태: 초안. 사용자 결정 3개를 받고 S8a 검증을 마친 뒤 구현한다.
근거: 공개 자료 조사(Opus), 로그인 상태 화면 기록 분석(Opus, 구조만), 설계 판단(Fable)

## 배경 (관찰)

- **SSO**
  - 포털에 로그인할 때만 폰 2단계 인증이 1회 있었다.
  - 같은 브라우저에서 ERP와 생활관(kds)은 SSO 세션으로 2단계 인증 없이 연쇄 로그인됐다(0.4~1.6초).
- **포털** (`portal.kaist.ac.kr/wz/api/...`, JSON)
  - 시간표: `POST widget/schedule/stulist`. 이번 학기, 30분 칸 단위로 온다. 과목코드·분반·요일·시각·강의실·교수가 들어 있다.
  - 학사일정: `GET widget/collegePlan?bgngDt&endDt`
  - 공지: `GET board/recents`(통합 목록), `board/recents/{pstNo}`(본문). 게시판은 64개다.
- **ERP** (`erp.kaist.ac.kr`, eXbuilder6)
  - 성적: `POST /sch/sgra/SgrassCtr/findStdntEtcGradeList.do`. 과목별 등급·학점과 학기별 평점이 온다. 누적 평점 필드는 없다.
  - ERP 시간표 화면은 암호화된 ClipReport 보고서라 재현할 수 없다. 그래서 시간표는 포털에서 가져온다.
- **생활관** (`kds.kaist.ac.kr`)
  - 배정 정보: `selectDormPostngInfo.do`(HTML), `selectDormPostngList.json`
  - 생활관 학기 일정: `semesterScheduleList.do`
  - 상태를 바꾸는 경로가 같은 화면에 있다: `dropOutAply`, `cancelDropOut`, `asignCancl`, `modifyAplyReason`. **호출 금지.**
- **공개 자료**
  - OTL(SPARCS, 비공식)에서 6과목 시간표가 정확히 나왔다.
  - 공개 학사일정의 중간고사 기간은 10/19~23, 기말고사 기간은 12/14~18이다.
- **미검증**
  - 쿠키만으로 HTTP 재현이 되는지
  - 쿠키 이름
  - 만료 응답
  - 포털에 먼저 로그인한 뒤 KLMS로 연쇄하는 흐름

## 결정 (권고안)

### 1. 로그인·세션
- `kaist login`은 한 번의 로그인 창에서 처리한다.
  - **포털에 먼저 로그인한다.** 2단계 인증은 여기서 1회만 한다.
  - 같은 브라우저 컨텍스트로 KLMS → ERP → kds를 차례로 연쇄 로그인한다.
  - 호스트별로 쿠키를 추출한다.
- 저장은 `session.json` v2: `{version:2, sites:{klms|portal|erp|kds:{cookies, savedAt, lastOkAt}}}`. 기존 v1은 자동으로 옮긴다.
- **SSO 쿠키는 저장하지 않는다**(v0.2 결정 유지). 사용자 개입 없이 세션을 새로 만드는 일을 막는다.
- 만료는 사이트별로 감지한다.

| 사이트 | 만료 감지 |
|---|---|
| KLMS | `/my/` |
| 포털 | 가벼운 API의 JSON·리다이렉트 응답 |
| ERP | `findNtcnCnt.do` |
| kds | 401 |

- `status --check`는 사이트 4개를 각각 보여준다.
- `kaist sync`에 필수인 것은 KLMS뿐이다. 포털 세션이 끝났으면 포털 단계를 건너뛰고 "재로그인 필요"를 알린다.
- 연쇄 로그인 중 한 사이트가 실패해도 나머지는 저장한다. `kaist login --only klms`로 KLMS만 로그인할 수도 있다.

### 2. 정보별 소스

| 정보 | 소스 | 비고 |
|---|---|---|
| 시간표 | 포털 `stulist` | 공식 데이터이고 실제 수강을 반영한다. OTL은 검증 때 1회 대조용으로만 쓴다 |
| 학사일정 | 포털 `collegePlan` | 구조화된 날짜 |
| 공지 | 포털 `board/recents` 증분 + 게시판 허용 목록 | 기존 글을 만나면 중단, 1회 최대 20쪽, 첫 백필은 30일, 수정일이 바뀌면 본문을 다시 받음. 첨부는 파일명만 |
| 성적 | ERP 성적 조회 1개 | 명시 명령으로만 |
| 기숙사 | kds 3개 호출 | |

### 3. 시간표 활용
- 정규 수업은 캘린더에 넣지 않는 것을 기본으로 한다(사용자 결정 1). 시간표는 로컬 DB에 두고 에이전트가 답할 때 쓴다.
- **휴강 규칙을 고친다** (S6의 "휴강은 종일"을 대체).
  - 그 날짜에 그 과목 수업이 **정확히 1개**면 수업 시각으로 등록한다. 설명에 "시각: 시간표 기준"을 넣는다.
  - 수업이 없거나 2개 이상이면 종일로 두고 B등급으로 내린다. 날짜를 잘못 해석했을 가능성이 크기 때문이다.
  - 온라인 수업과 보강도 같은 규칙을 쓴다.
- **시각 미정인 시험에는 수업 시각을 쓰지 않는다.** 실제 시험 시각이 수업 시각과 다른 사례가 확인됐다. 설명에 참고로만 적는다.

### 4. 학사 공지·학사일정
- 포털 공지는 1차에서 학사 일정 후보 출처로 쓰지 않는다. 과목 매핑이 없기 때문이다.
- 공식 학사일정(`collegePlan`)은 새 종류 `school`로 자동 등록한다. 공식 값이라 해석할 필요가 없다.
  - 허용 목록(사용자 결정 2) 안의 항목만 등록한다.
  - 기간 일정은 여러 날에 걸친 종일 일정으로 넣는다.
  - 색은 10번이다.
  - 학교가 날짜를 바꾸면 그 일정을 수정하고 이력을 남긴다.
  - `events undo`로 되돌릴 수 있다.

### 5. 성적 (민감 정보)
- **저장:** `%LOCALAPPDATA%`의 SQLite에만 둔다.
- **내보내지 않음:** 드라이브, 요약, PDF, 캘린더, `changes`, sync 브리핑, 로그, 오류 메시지에 값이 나가지 않는다. 테스트로 확인한다.
- **조회:** `kaist grades --refresh`라는 명시 명령으로만 ERP에 접속한다. `sync`에는 넣지 않는다. 표시는 `kaist grades --json`으로 한다.
- **누적 평점:** 학기별 값으로 계산하고 `computed: true`와 "공식값은 ERP" 표시를 붙인다.
- **에이전트 규칙:**
  - 사용자가 물을 때만 조회하고, 먼저 꺼내지 않는다.
  - 결과를 어디에도 쓰지 않는다.
  - 조회 시각을 함께 말한다.

### 6. 기숙사
- 배정 정보와 생활관 학기 일정을 로컬에 저장한다. 표시는 `kaist dorm --json`이다.
- 드라이브에는 올리지 않는다. 호실은 거주지 정보다.
- 캘린더:
  - 입사·퇴사·거주기간 만료는 종류 `dorm`으로 자동 등록한다.
  - 생활관 일정은 허용 목록 안의 것만 등록한다(사용자 결정 2).
- `changes`에는 "기숙사 정보 변경"만 적고 값은 넣지 않는다.

### 7. 안전장치
- **허용 목록:** 사이트 어댑터마다 `(method, path, 목적)` 고정 표를 두고, HTTP 계층이 표에 없는 URL을 거부한다.
- 단위 테스트로 표에 변경 동사(Aply, Cancel, modify, save, delete, insert, update, regist, drop)가 없음을 확인한다. kds 금지 경로는 테스트로 명시한다.
- 로그인 창에서 CLI는 이동만 한다. 폼 조작이나 클릭은 하지 않는다.
- 수강신청·변경·취소 기간에는 포털·ERP·kds에 자동 접속하지 않는다(`quietWindows`, `collegePlan`에서 자동으로 계산). `--force`로만 접속한다. KLMS는 해당되지 않는다.
- 동시 요청은 1개, 요청 간격은 500ms 이상이다. 폴링은 재현하지 않는다. 응답 본문은 로그에 남기지 않는다.

## S8a 검증 목록 (로그인 1회, 항목마다 요청 1~2건, 결과는 samples에만)

1. 연쇄 로그인 뒤 호스트별 쿠키 이름·도메인. SSO 쿠키를 빼도 각 사이트가 동작하는지.
2. 포털: 쿠키 + fetch로 `stulist`, `collegePlan`, `recents`가 재현되는지. 필요한 헤더. 만료 응답의 형태.
3. ERP: 요청 인코딩과 `_menuId`/`_pgmId`가 고정값인지. 성적 응답 구조. 만료 응답. 프로브.
4. kds: `AJAX: true` 헤더로 배정 정보 HTML이 재현되는지. 401 형태.
5. 포털에 먼저 로그인한 뒤 KLMS 연쇄가 2단계 인증 없이 되는지. 기존 KLMS 흐름이 그대로인지.
6. 세션 수명(사이트별).
7. `recents`가 전체 게시판의 합집합인지, `pstNo`가 계속 증가하는지.
8. `stulist` 결과와 OTL·KLMS 과목 목록 대조.
9. `collegePlan`과 공개 학사일정 대조.

## 단계와 완료 기준

- **S8a 로그인·검증**
  - 2단계 인증 1회로 4개 사이트의 쿠키를 저장한다.
  - 브라우저를 닫은 뒤 프로브 4개가 통과한다.
  - 쿠키를 망가뜨리면 사이트별로 만료를 판별한다.
  - 검증 결과를 이 문서에 기록한다.
- **S8b 시간표·학사일정·기숙사**
  - `timetable`, `dorm` 명령과 학교·기숙사 일정 자동 등록, 휴강 시각 개정, `quietWindows`를 만든다.
  - 시간표가 OTL과 일치한다. 시험 기간이 공개 학사일정과 일치한다. 기숙사 일정이 휴대폰 캘린더에 보인다.
- **S8c 학사 공지**
  - `notices --source portal`과 드라이브 `_학교공지.md`(제목 목록)를 만든다.
  - 두 번 연속 sync해도 중복이 0이다.
- **S8d 성적**
  - `grades --refresh`를 만든다.
  - 격리 테스트(드라이브·요약·로그에 성적이 없음)를 통과한다.
  - sync가 ERP에 접속하지 않는다.

## 사용자 결정 필요

1. 정규 수업을 캘린더에 반복 일정으로 넣을지 → 권고: 넣지 않음. 로컬 시간표와 휴강 시각에만 쓴다.
2. 학교·생활관 일정 자동 등록 범위 → 권고: 아래 항목만 자동으로 넣고, 나머지는 로컬에서 조회만 한다.
   - 수강신청·변경·취소 기간
   - 시험 기간
   - 휴일
   - 개강·종강
   - 성적 공시
   - 등록금
   - 입사·퇴사
3. 포털 공지 범위 → 권고: 수강/학적(31)·장학/복지(28)·생활관(45)은 본문까지 로컬에 저장한다. 세미나(23)는 제목만 저장한다. 드라이브에는 제목 목록만 올린다.

   - 수강/학적(31), 장학/복지(28), 생활관(45): 본문까지 로컬에 저장한다.
   - 세미나/행사(23): 제목만 저장한다.
   - 드라이브에는 제목 목록(`_학교공지.md`)만 올린다.
