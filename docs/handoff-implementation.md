# 구현 인수인계 문서 (Claude Code용)

작성일: 2026-10-13
이 문서를 `docs/handoff-implementation.md`로 넣고 Claude Code에 "docs/handoff-implementation.md를 읽고 이어서 진행해줘"라고 시킨다.

이 문서 이후로는 설계 상담 없이 **Claude Code와 사용자 둘이서** 끝까지 진행한다. 판단이 필요한 일은 이 문서의 기준으로 정하고, 기준에 없으면 사용자에게 묻는다.

---

## 1. 읽을 문서와 우선순위

1. 이 문서
2. `docs/phase0-report.md` (검증 결과. 특히 3절 설계 변경 제안)
3. `docs/kaist-agent-design.md` v0.1 (요구사항과 범위)

내용이 충돌하면 위 순서대로 우선한다. v0.1 설계의 인증 흐름과 수집 방식은 0단계 결과로 대체됐다.

## 2. 확정된 결정

0단계 보고서 5절의 질문에 대한 결론이다.

| 항목 | 결정 |
|---|---|
| WS 토큰 | **쓰지 않는다.** `launch.php`, `webservice/rest`, `tool_mobile_*` 호출 코드를 넣지 않는다. 옵션으로도 두지 않는다 |
| 수집 방식 | 보고서 3.1 그대로: 쿠키 + sesskey AJAX + HTML 파싱. Playwright는 로그인 전용 |
| 위험 완화 | 보고서 3.2 그대로: 마감 값은 캘린더 유닉스 초만 사용, HTML과 다르면 `needs_review`, 불변식 검사 |
| 로그인 판별, 만료 감지, 인증 흐름 | 보고서 3.3, 3.4, 3.5 그대로 |
| 비밀번호 | 사용자가 매번 직접 입력한다. CLI는 비밀번호를 저장하거나 자동 입력하지 않는다. 브라우저 자동완성도 쓰지 않으므로 로그인마다 새 브라우저 컨텍스트를 쓴다 (persistent profile 불필요) |
| 승인 횟수 줄이기 | 1차에서는 하지 않는다. 세션 유지용 주기적 요청, SSO 쿠키 저장·재주입 모두 구현하지 않는다. 세션이 살아 있으면 재사용하고, 만료되면 다시 로그인한다 |
| 다운로드가 막힌 자료 | 우회하지 않는다. "뷰어 전용"으로 목록에만 기록한다 |
| 서버에 발급된 토큰 | 다시 쓰거나 재발급하지 않고 그대로 둔다 |
| 비밀값 위치 | 쿠키, 구글 OAuth 토큰, 수집 기록 DB, HTML 원문 보관본은 `%LOCALAPPDATA%\kaist-cli\`에 둔다. OneDrive와 구글 드라이브 폴더에는 절대 두지 않는다 |
| 실행 환경 | 개인 Windows PC만. 서버, 백그라운드 실행 없음 |

## 3. 가장 먼저 사용자와 처리할 것

구현 전에 아래를 순서대로 처리한다. 질문은 한 번에 하나씩 한다.

1. **`wstoken.txt` 삭제 확인.** 권고는 삭제다. 되돌릴 수 없으므로 사용자에게 확인을 받고 지운다. 지운 뒤 `check-session.ts`의 `--token` 옵션과 토큰 관련 코드도 제거한다.
2. **OneDrive 정리 안내.** OneDrive 웹의 휴지통에서 옛 `local/` 사본(쿠키, 토큰 파일 포함)을 비우도록 사용자에게 안내한다. 이 작업은 사용자가 직접 해야 한다. 했는지 확인받는다.
3. **세션 유지 측정 결과 반영.** `session-checks.log`에 쌓인 결과가 있으면 보고서 V2 표에 반영한다. 없으면 사용자에게 실행을 부탁하되, 구현은 기다리지 않고 진행한다. 설계는 "세션이 언제든 만료될 수 있다"를 전제로 하므로 측정값이 구현을 막지 않는다.

## 4. 작업 순서

**한 세션에 한 단계씩** 진행한다. 각 단계가 끝나면 완료 기준을 직접 실행해 확인하고, 결과를 사용자에게 보여준 뒤 멈춘다. 사용자가 확인하면 커밋하고 다음 단계로 간다.

### S0. 설계 문서 v0.2 작성

- `docs/kaist-agent-design.md`를 v0.2로 고친다. 이 문서 2절의 결정과 보고서 3절을 반영한다.
  - 4절 구조도, 5절 인증 흐름, 7절 저장 위치, 11절 가정 표(A8, A9 추가), 13절 위험 요소(HTML 의존, 토큰 발급 사실과 미사용 결정)
- `CLAUDE.md`를 만든다. 프로젝트 목적, 이 문서의 5절 규칙, 폴더 구조, 현재 단계를 적는다. 단계가 끝날 때마다 "현재 단계"를 갱신한다.
- 아래 미결 사항을 사용자에게 하나씩 물어 확정하고 설계 문서에 적는다.
  - CLI 이름 (임시: `kaist`)
  - 구글 드라이브 동기화 폴더의 실제 경로와 폴더 이름 규칙 (과목명만 쓸지, 과목 코드를 붙일지)
- 완료 기준: v0.2 문서와 CLAUDE.md가 있고, 사용자가 읽고 승인했다.

### S1. 인증과 과목 목록

- 명령: `login`, `status`, `courses`
- 세션 저장소(쿠키 파일), 세션 프로브, 로그인 완료 판별, 만료 판별 함수
- HTTP 클라이언트 공통 계층: 브라우저 형태 User-Agent, 요청 간격, 동시 요청 2개 이하, 만료 감지 통합
- 과목 목록 AJAX 호출과 이번 학기 필터. 필터 결과가 0건이면 실패로 처리한다
- 모든 조회 명령에 `--json` 출력
- 완료 기준: 새로 로그인한 뒤 `courses`가 이번 학기 7과목을 출력한다. 브라우저를 닫은 뒤 다시 실행해도 재로그인 없이 동작한다. 쿠키 파일을 일부러 망가뜨리면 만료로 판별하고 로그인을 요청한다.

### S2. 과목 구성, 과제, 공지 수집

- 명령: `sync`(파일 다운로드와 캘린더 제외), `assignments`, `notices`, `videos`, `doctor`
- 과목 페이지(`section=0`) 파서, 과제 페이지 파서, courseboard 목록·본문 파서
- 캘린더 월별 조회로 마감 수집, `instance`=cmid 매핑, HTML `end-dt`와 교차 검증, `needs_review` 처리
- 수집 기록 DB(SQLite)와 증분 수집
- 보고서 3.2의 불변식 1~3 구현. `core_course_get_updates_since`(since=0)가 전체 모듈을 돌려주는지 먼저 확인하고, 아니면 불변식 1의 대체안을 사용자와 정한다
- 셀렉터는 어댑터 파일 한 곳에 모은다
- 파서 테스트: 저장한 HTML 샘플을 입력으로 쓴다. 샘플에 개인정보가 있으므로 저장소에 넣지 않고 `%LOCALAPPDATA%\kaist-cli\samples\`에서 읽는다. 날짜 변환(Asia/Seoul 고정, "오전 12:00" = 00:00)은 개인정보 없는 단위 테스트로 저장소에 넣는다
- 완료 기준: `sync` 후 `assignments`의 마감이 KLMS 화면과 일치한다(사용자가 과제 3개 이상을 직접 대조). 두 번째 `sync`는 변경분만 처리한다. `doctor`가 모든 과목에서 불변식 통과를 보고한다.

### S3. 강의자료 다운로드와 폴더 정리

- 파일 다운로드: HEAD로 `ETag`/`Last-Modified`/`Content-Length`를 비교한 뒤 받는다. 바뀐 파일은 이전 버전을 지우지 않고 새 버전을 따로 저장한다
- 과제 첨부, 게시판 첨부 다운로드 (게시판 첨부는 0단계에서 미검증이므로 작은 파일 1개로 먼저 확인)
- 드라이브 폴더 구조와 `_요약.md`, `_과목정보.md` 생성. 맨 위에 마지막 수집 시각을 적는다
- 영상은 받지 않는다. 제목과 KLMS 링크만 `_과목정보.md`에 적는다
- 명령: `files [--new]`
- 첫 전체 다운로드 전에 예상 파일 수와 용량을 사용자에게 보여주고 진행 여부를 확인받는다
- 완료 기준: 7과목의 자료가 과목별 폴더에 있고, 파일 수가 KLMS와 맞는다. 다시 `sync`하면 새로 받는 파일이 0개다. 모바일 드라이브 앱에서 `_요약.md`가 열린다(사용자 확인).

### S4. 구글 캘린더

- 구글 클라우드 프로젝트와 OAuth 클라이언트 발급을 사용자에게 단계별로 안내한다 (사용자가 직접 해야 한다)
- "KLMS" 전용 캘린더 생성, 마감 등록, 이벤트 비공개 속성에 cmid를 기록해 중복 방지
- 마감이 바뀌면 기존 이벤트를 수정한다. 과제가 사라지면 삭제하지 않고 제목에 표시한다. `needs_review` 과제는 등록하지 않는다
- 이벤트 설명에 KLMS 원문 링크와 마지막 수집 시각
- 명령: `cal list/add/update/delete/push`. 쓰기는 전용 캘린더로 제한하고, 다른 캘린더는 명시적 옵션이 있을 때만 허용한다
- 이 단계 시작 시 사용자에게 물어 정할 것: 이벤트 제목 규칙, 알림 시점, 마감을 시각 일정으로 넣을지 종일 일정으로 넣을지
- 완료 기준: `sync` 후 전용 캘린더의 마감이 `assignments` 출력과 일치한다. `sync`를 두 번 돌려도 중복 이벤트가 없다. 모바일 캘린더 앱에서 보인다(사용자 확인).

### S5. 에이전트 연결과 다듬기

- CLAUDE.md에 에이전트용 사용 안내를 적는다: 각 명령의 용도와 출력 형식, "조회는 로컬 데이터로 답하고 최신화가 필요하면 sync를 제안하며 폰 승인을 요청한다", 과제 풀이 논의 때 읽을 파일, 캘린더 삭제는 실행 전 확인
- 사용자와 실제 대화 시나리오를 돌려 본다: "새로 올라온 거 확인해줘", "이번 주 마감 뭐 있어?", "○○ 과제 같이 풀어보자", "이 마감을 작업 일정으로도 넣어줘"
- 불편한 출력과 빠진 명령을 고친다
- README에 설치 방법과 고장 났을 때 점검 순서(`doctor`, 셀렉터 파일 위치)를 적는다
- 완료 기준: 위 시나리오가 추가 설명 없이 동작한다.

## 5. 작업 규칙

**사용자와의 소통**
- 질문은 한 번에 하나씩 하고, 왜 묻는지 배경을 설명한다. 답을 받은 뒤 다음 질문으로 넘어간다.
- 필요한 정보가 없으면 추측하지 말고 묻는다.
- 결과는 과장 없이 보고한다. 안 된 것, 확인하지 못한 것을 축소하지 않는다. 관찰과 추정을 구분한다.
- 문서 산출물은 `.md` 파일로 만든다.

**KLMS 접근**
- 읽기만 한다. 제출, 글쓰기, 설정 변경 등 상태를 바꾸는 요청은 코드에 넣지 않는다.
- 이번 학기 수강 과목만 대상으로 한다. 사용자 검색이나 다른 과목 탐색은 하지 않는다.
- 요청은 천천히 보낸다(간격을 두고, 동시 2개 이하). 개발 중 반복 실행은 저장한 샘플로 하고, 실제 서버 요청은 최소로 한다.
- 2단계 인증을 우회하지 않는다. 비밀번호를 묻거나 저장하지 않는다.
- 교수가 다운로드를 막은 자료와 스트리밍 영상은 받지 않는다.
- 받은 강의자료는 사용자 개인 학습용이다. 공유 기능은 만들지 않는다.

**코드**
- TypeScript, Node.js. 사이트별 코드는 어댑터로 분리하고 SSO 모듈은 KLMS와 분리한다.
- 파싱에 실패하면 조용히 넘어가지 않고 무엇이 어디서 깨졌는지 명확한 오류를 낸다.
- 비밀값과 개인정보가 저장소, 로그, 문서에 들어가지 않게 한다. 커밋 전에 확인한다.

**멈추고 사용자에게 알릴 상황**
- 로그인이 막히거나 캡차, 차단 문구가 뜬다
- 요청이 차단되거나 평소와 다른 오류가 반복된다
- 불변식 검사가 실패한다
- 이 문서의 결정을 바꿔야 할 이유가 생긴다 (예: 필요한 정보를 토큰 없이는 얻을 수 없다). 이 경우 임의로 바꾸지 않고 근거와 선택지를 설명한 뒤 사용자의 결정을 받는다

## 6. 미검증 항목

해당 사례를 만나면 그때 확인하고, 보고서 4절에 결과를 적는다.

| 항목 | 만났을 때 할 일 |
|---|---|
| 퀴즈 | 캘린더 open/close 이벤트와 `mod/quiz/view.php` HTML로 확인. 부족하면 HTML 보강으로 해결한다 (토큰 아님) |
| 폴더 모듈 | `mod/folder/view.php` HTML에서 파일 링크 추출 확인 |
| 개인·그룹 마감 연장 이벤트 | 보고서 3.2의 우선순위(본인 → 그룹 → 과목 전체) 적용, 후보가 둘 이상 남으면 `needs_review` |
| `core_course_get_updates_since`(since=0)의 범위 | S2에서 확인 |
| 게시판 첨부 다운로드, 고정 공지, 비밀글 | S2~S3에서 확인 |
| 뷰어 전용 자료 | 발견하면 받지 않고 목록에만 기록. HTML에서 어떻게 보이는지 적어 둔다 |
| 세션 실제 유지 시간 | 사용자 측정 결과 반영 |

모르는 활동 유형을 만나면 건너뛰되, sync 결과에 "처리하지 못한 활동 유형과 개수"를 출력한다.

## 7. 1차 범위 밖

아래는 1차(S0~S5)가 끝나고 사용자가 요청할 때만 시작한다. 그때는 새 설계 문서를 먼저 쓴다.

- Dooray 메일, Gmail 읽기와 메일 초안 작성
- Portal, 기숙사 사이트 조회
- 카카오톡 연동
- KLMS 과제 제출

아래는 만들지 않는다.

- 수강신청, 기숙사 신청 등 경쟁성 신청의 자동화
- 2단계 인증 우회, 비밀번호 자동 입력
- 스트리밍 영상 추출

## 8. 알려진 한계 (사용자가 받아들인 것)

- 새 과제를 자동으로 알려주지 않는다. PC에서 sync를 실행해야만 갱신된다.
- 로그인할 때마다 비밀번호 입력과 폰 승인이 필요하다.
- KLMS가 개편되면 HTML 파서가 깨질 수 있다. `doctor`와 불변식으로 감지하고 셀렉터 파일을 고친다.
- 초기 몇 주는 캘린더의 마감을 KLMS와 직접 대조해야 한다.
