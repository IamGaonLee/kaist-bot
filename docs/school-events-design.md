    - 강의계획서 일정표: "Oct 19 Midterm", "12/14 Final Exam 9:00-11:45", "Nov 16-27 make-up TBA"
  - 잡음:
    - 기출문제 PDF 속 지난 날짜

  - 스캔 PDF는 텍스트가 없다.
- 임시 조치(2026-10-14, 사용자 승인): 찾은 중간·기말 8건을 `kaist cal add`로 직접 등록했다.

  - 출처가 강의계획서면 "(계획서 기준)", 시간을 모르면 종일 "(시간 미정)"

## 결정

### 1. 추출 방식: CLI 후보 필터 + 에이전트 해석 + CLI 검증 등록

- **CLI**(sync 끝에): 키워드와 날짜 힌트가 ±150자 안에 함께 있는 구간만 후보로 DB에 쌓는다. LLM은 호출하지 않는다.
  - 키워드: 시험, 중간, 기말, 퀴즈, 휴강, 보강, 온라인, 비대면, zoom, midterm, final, exam, quiz, no class, cancel, make-up, online
  - 날짜 힌트: `10/22`, `10월 22일`, `Oct 22`, `2026-10-22`, 요일, `13:00`
  - 지난 연도가 적힌 구간과, 파일명에 기출·past·지난 연도가 있는 파일은 `past`로 자동 분류한다.
  - 이미 본 후보는 기억해서, 새 후보만 보여준다.
- **에이전트**(Claude Code 대화): `kaist events candidates --new --json`을 읽고 해석한다.
  - 연도 보정(게시일과 학기 범위로)
  - 요일 대조, 상대 표현 풀기
  - 출처 우선순위, 중복·변경 판단
- **CLI 등록 전 기계 검증**(`events add/update`):
  - (i) `--quote`가 후보 원문에 실제로 있는 문자열인지 확인한다. 지어낸 값을 막는다.
  - (ii) 인용문에 요일이 있으면 날짜와 요일이 맞는지 확인한다.
  - (iii) 날짜가 이번 학기 범위 안이고, 미래이거나 지난 지 7일 이내인지 확인한다.
  - (iv) 시험인데 시각이 없으면 종일 + "(시간 미정)"으로만 허용한다.
- 버린 대안:
  - 정규식만으로 처리: 상대 표현과 번복을 못 푼다.
  - CLI가 Claude API를 직접 호출: API 키와 비용이 들고, 사람 없이 해석부터 등록까지 이어진다.

### 2. 자동 등록 범위 (사용자 결정: **처음부터 자동**)

- **A등급: 확인 없이 등록하고, sync 브리핑에서 보고한다.** 아래를 모두 만족해야 한다.
  - 출처가 **공지(courseboard)** 또는 **주차 안내**다. 강의계획서, 과제 설명, 파일, 메일은 제외한다.
  - 월·일이 명시된 절대 날짜이고, 연도가 학기 범위로 하나로 정해진다.
  - 시험은 시작 시각까지 있어야 한다. 휴강·온라인은 날짜만 있으면 종일로 등록할 수 있다.
  - 1절의 기계 검증을 통과했다.
  - 같은 (과목, 종류, 날짜) 일정이 아직 없다. 이미 있으면 변경이므로 B등급이다.
  - 종류가 exam, no_class, online 중 하나다.
- **B등급: 사용자 확인 후 등록한다.**
  - 강의계획서 출처. 등록할 때 제목에 "(계획서 기준)"을 붙인다(사용자 결정).
  - 상대 표현이나 요일만 있는 표현
  - 시각을 모르는 시험
  - 기존 일정의 변경·취소
  - 출처끼리 불일치
  - 메일 출처(첫 학기 동안)
  - 보강과 기타
- **출처 우선순위**: 같은 과목에서는 최신 글이 이긴다. 시점을 비교할 수 없으면 공지 > 주차 안내 > 강의계획서 > 기타 순이다. 강의계획서는 공지를 덮어쓰지 못한다. 덮인 후보는 `superseded`로 둔다.
- **변경과 취소**
  - 일정은 제자리에서 수정하고, 설명에 "이전: …" 줄을 남기고, 이력 테이블에 기록한다.
  - 취소된 일정은 지우지 않고 제목 앞에 `[취소]`를 붙인다.
  - 같은 날짜에 시간만 채워지는 경우는 A등급으로 본다.
- **중복 방지 키**
  - 일정: `(course_id, kind, date)`, 구글 비공개 속성 `kaistEventKey=ev:<course>:<kind>:<YYYY-MM-DD>`
  - 후보: `(source_type, source_id, snippet_hash)`. 원문이 바뀌면 다시 후보가 된다.
- **되돌리기**
  - 모든 등록에 `created_by_sync_id`와 `confidence(auto|confirmed)`를 남긴다.
  - `kaist events undo --last`는 대상 목록을 먼저 보여주고 `--yes`가 있어야 실행한다.
  - 브리핑에는 항상 "자동 등록 N건 (되돌리기: `events undo --last`)"을 붙인다.

### 3. 캘린더 표현 (임시 조치와 같은 규칙)

- 같은 "KLMS" 캘린더를 쓰고 `colorId`로 구분한다.
  - 시험: 11(빨강)
  - 휴강: 8(회색)
  - 온라인: 9(파랑)
  - 보강: 6(주황)
- 제목 규칙
  - 시험: `[과목명] 중간고사|기말고사|퀴즈 N`. 시각이 있으면 실제 시작~끝으로 넣고 장소는 `location`에 넣는다. 시각이 없으면 종일 + "(시간 미정)"이다.
  - 휴강: `[과목명] 휴강`, 종일. 수업 시각을 추정하지 않는다. 시간표는 Portal을 연결한 뒤에 다룬다.
  - 온라인 수업: `[과목명] 온라인 수업`. 종일로 넣되, 글에 시각이 있으면 시각 일정으로 넣는다. 링크는 설명에 넣는다.
  - 보강: 시각과 장소가 있을 때만 시각 일정으로 넣고, 없으면 종일 "(시간 미정)"이다.
- 설명에 넣는 내용
  - 자동 해석 여부(auto/확인됨)
  - 원문 인용
  - 출처 제목과 KLMS 링크
  - 마지막 수집 시각
  - (변경된 경우) 이전 값
- 알림
  - 시험: 7일 전, 1일 전
  - 휴강·온라인·보강: 1일 전
  - 종일 일정은 전날 09:00 기준

### 4. 데이터 모델과 명령

- 테이블
  - `source_text`: 파일 텍스트 캐시. 텍스트가 없는 파일은 `no_text`로 표시한다.
  - `event_candidates`: 상태는 new, linked, dismissed, superseded, past, stale
  - `school_events`
  - `school_event_history`
- 명령
  - `kaist events candidates [--new] [--course] [--kind] --json`
  - `kaist events add --course --kind --date [--start --end --location --title] --from-candidate <cid> --quote "<원문>" [--confirmed] [--dry-run]`. `--source manual`이면 후보 없이 쓸 수 있다.
  - `kaist events update <id> (--date|--start|--end|--location|--cancel) --from-candidate --quote`
  - `kaist events dismiss <cid> [--reason]`
  - `kaist events list [--from --to] [--auto] [--sync <id>]`
  - `kaist events undo (--last|--sync <id>) [--yes]`
- 역할 구분
  - `cal add`: 출처 없는 임의 일정(작업 시간 등)
  - `events add`: 출처가 있는 학사 일정

### 5. 단계

- 순서는 S5 → **S6**(KLMS 출처: 공지, 주차 안내, 강의계획서 파일 텍스트) → Dooray 메일(`source_type=mail` 추가, 새 설계 문서) → Portal이다.
- S6 완료 기준
  - sync 후 새 후보가 브리핑에 나온다.
  - A등급 공지 1건 이상이 자동 등록되고, `events undo --last`로 되돌릴 수 있다.
  - 강의계획서 후보가 공지를 덮어쓰지 않는다.
  - 임시로 등록한 8건이 `school_events`로 옮겨진다.
