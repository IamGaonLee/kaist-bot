# S7 설계: 학교 메일(Dooray) 연결

- **작성:** 2026-10-14
- **상태:** 초안. 사용자 확인 대기. 아래 "결정 필요" 항목을 정하고 전제(전달 가능 여부)를 확인한 뒤 구현한다.
- **근거:** 공개 자료 조사(Opus)와 설계 판단(Fable)

## 배경 (조사 결과)

- KAIST 메일은 **공공기관용 Dooray**(gov-dooray.com)다.
  - 2021년 4월에 전환했다. MX 레코드는 `aspmx1.gov-dooray.com`이다.
  - 웹메일 주소는 `mail.kaist.ac.kr`이고, 포털 SSO와 2단계 인증으로 로그인한다.
- **IMAP/POP3는 쓸 수 없다.**
  - 전환할 때 "POP3/IMAP서비스가 중지"된다고 공지했다(카이스트신문, 2021-03-03).
  - Dooray 공식 문서: "IMAP is not provided for public institutions."
- **Dooray 메일 REST API는 찾지 못했다.** 공개 자료와 서드파티 도구 모두 프로젝트·메신저·캘린더만 다룬다.
- **외부 자동 전달**
  - 졸업생 메일은 외부 전달을 제공한다고 명시돼 있다.
  - 같은 gov-dooray를 쓰는 서울대도 외부 자동 전달을 안내한다.
  - KAIST 재학생 계정에서 되는지는 **확인하지 못했다**. 사용자가 Dooray 설정 화면에서 직접 확인해야 한다.

## 결정 (권고안)

### 1. 접근 방식: Dooray → Gmail 자동 전달 + CLI가 Gmail API(`gmail.readonly`)로 읽기

- CLI는 Gmail 라벨 `KAIST`가 붙은 메일만 가져와 로컬 DB(`mails`)에 저장한다.
- S6 학사 일정 후보 추출은 메일 본문을 출처(`source_type=mail`)로 삼는다. `events add --quote` 검증도 이 본문에 대고 한다.
- 이렇게 하는 근거
  - S6의 핵심 안전장치는 "CLI가 직접 받아온 원문에 인용이 실제로 있는가"다. 메일 본문도 CLI 경로로 들어와야 이 검증이 유지된다.
  - 이미 있는 구글 OAuth 구조를 재사용한다. 앱이 '테스트' 상태라 제한 범위도 테스트 사용자에게 심사 없이 허용된다(동의 화면에서 확인할 것).
  - KAIST 비밀번호를 전혀 다루지 않는다.
- 보조 수단
  - 에이전트가 쓰는 Gmail 커넥터(MCP)는 대화 중 즉석 조회("그 메일 뭐랬지?")와 구현 전 관찰에만 쓴다.
  - 커넥터로 읽은 내용을 학사 일정 등록 근거로 쓰지 않는다.
- 버린 대안
  - **Dooray 웹메일 브라우저 세션:** 공개되지 않은 내부 구조에 의존해 깨지기 쉽다. 세션이 KLMS와 별개면 2단계 인증 로그인 횟수도 늘어난다. 외부 전달이 막혀 있을 때의 최후 수단으로만 남긴다.
  - **MCP 단독:** 상태가 CLI 밖에 남고, 원문 검증 사슬이 끊긴다.

### 2. 개인정보 원칙

- **전달**
  - Dooray 원본은 반드시 보관한다. 공식 기록은 Dooray다.
  - Gmail 필터로 라벨 `KAIST`를 붙인다.
  - 전달은 설정한 뒤 받는 메일에만 적용된다.
- **로컬 DB 저장 범위**
  - 모든 라벨 메일: 발신자, 제목, 수신 시각, 스니펫 200자, 첨부 파일명만 저장한다.
  - 본문 전문(텍스트): `kaist.ac.kr` 발신(하위 도메인 포함)이거나 config의 허용 발신자일 때만 저장한다.
  - 제목에 성적, 등록금, 장학, 급여, 상담, 건강검진 같은 말이 있으면 KAIST 발신이어도 메타데이터만 저장한다.
- **보존:** 본문은 수신 90일 뒤에 지운다. 학사 일정 후보에 연결된 메일은 학기 말 + 30일까지 남긴다.
- **첨부:** 첫 학기에는 받지 않고 파일명만 기록한다.
- **출력:** `mail list`에는 본문이 없다. 본문은 `mail show`로만 본다. 메일 본문은 로그, 문서, 저장소에 넣지 않는다.

### 3. 학사 일정 등급

- 메일에서 나온 후보는 **첫 학기 동안 B등급**(확인 후 등록)으로 둔다.
  - 메일에는 과목 ID가 없어 어느 과목인지 추정해야 한다.
  - 학과 전체 공지, 전달된 메일, 여러 과목 언급이 섞여 있다.
- 예외: 이미 있는 일정에 시각만 채우는 경우는 S6 규칙대로 A등급이다.
- 다음 학기 검토 기준: 확인 후 등록 20건 이상, 오해석 0건

### 4. 명령과 데이터 (초안)

- **명령**
  - `kaist google login`: 캘린더와 Gmail 권한을 한 번에 동의한다. `cal login`은 별칭으로 남긴다.
  - `kaist mail sync [--since 7d]`: 새 메일만 가져온다. 저장 정책을 적용하고, 학사 일정 후보를 추출한다. `kaist sync` 끝에도 실행한다. 실패해도 KLMS 수집은 유지한다.
  - `kaist mail list [--since 3d] [--academic] [--course X]`: 헤더와 스니펫
  - `kaist mail show <id>`: 본문
  - `kaist doctor`: 저장 정책 위반과 보존 기간 초과를 검사한다.
- **데이터**
  - `mails` 테이블: Gmail id, 스레드, 수신 시각, 발신, 제목, 스니펫, `body_text`(정책에 따라 null), `body_policy`, 첨부 이름, 추정 과목, 과목 매핑 근거
  - `event_candidates`는 그대로 쓴다(`source_type='mail'`).
  - 워터마크: 마지막 수신 시각과 historyId
  - config: `mail: { enabled, label, senderAllow, bodyRetentionDays, excludeSubjectKeywords }`
- **주의:** 전달된 메일의 발신자가 원발신자로 유지되는지는 첫 테스트 메일로 확인해야 한다. 유지되지 않으면 본문의 원발신 헤더를 읽는 어댑터를 추가한다.

## 사용자가 할 일

1. **(전제)** Dooray 웹메일 설정에서 외부 자동 전달이 되는지 확인한다. 안 되면 여기서 멈추고 브라우저 세션 방식을 다시 검토한다.
2. 전달 주소를 Gmail로 등록하고 인증한다. **원본 보관**을 켠다.
3. Gmail 필터를 만든다: `to:<KAIST 주소>` → 라벨 `KAIST`
4. Google Cloud 콘솔에서 Gmail API를 켜고, 동의 화면에 `gmail.readonly` 범위를 추가한다.
5. 본인 KAIST 주소로 테스트 메일을 1통 보낸다. Gmail에 라벨이 붙어 오는지, 발신자가 유지되는지 확인한다.
6. 구현이 끝나면 `kaist google login`으로 다시 동의한다(OAuth 앱 게시 뒤로는 7일 만료 없음).
7. 이미 받은 메일은 전달되지 않는다. 필요한 것만 직접 전달한다.

## 결정 필요 (사용자)

1. **전달 범위:** 전체 전달인가, KAIST 발신만 전달인가 → 권고는 전체 전달이다. 구분은 Gmail 라벨과 CLI의 저장 정책이 맡는다.
2. **본문 저장·보존:** 위 2절 권고안인가, 전부 저장인가 → 권고는 2절 권고안이다.
3. **구글 토큰:** 캘린더와 Gmail을 한 토큰으로 묶을 것인가 → 권고는 통합이다. 7일 재로그인이 한 번으로 끝난다.

## 구현 전 관찰 (권고)

- 전달만 켜 두고 1주일쯤 둔다.
- 에이전트가 Gmail 커넥터로 `label:KAIST`를 훑어 발신자 형태, 하루 평균 통수, 학사 공지 비율을 본다.
- 이 결과로 허용 발신자와 제외 키워드의 기본값을 정한다.

## 확인과 결정 (2026-10-14)

- **전달 상태 (관찰):** Dooray → Gmail 자동 전달이 이미 켜져 있다.
  - 최근 14일 동안 약 200통이 왔다(하루 약 14통).
  - 발신자는 원래 보낸 사람(@kaist.ac.kr)이 그대로 유지된다. 그래서 전달 메일용 어댑터는 필요 없다.
  - 대부분은 학과·학교 전체 메일링 리스트(gr_stud 등)로 온 것이다. 교수나 개인이 직접 보낸 메일은 일부다.
  - 별도 라벨은 없고 받은편지함에 섞여 있다.
- **Gmail 필터·라벨:** 만들지 않는다.
  - Gmail 계정에는 개인 메일도 많다. CLI는 `{from:kaist.ac.kr to:kaist.ac.kr cc:kaist.ac.kr}` 조건으로 KAIST에서 전달된 메일만 가져온다.
  - 개인 Gmail 메일은 가져오지 않는다.
- **전달 범위:** 이미 전체 전달이므로 그대로 둔다.
- **본문 저장 (사용자 결정: 전부 저장):**
  - 위 조건에 맞는 메일은 발신 도메인이나 제목과 관계없이 본문을 저장한다. 보존 기한도 두지 않는다.
  - 저장 위치는 `%LOCALAPPDATA%\kaist-cli\kaist.db`뿐이다. 첨부는 첫 단계에서는 파일명만 기록한다.
  - 2절의 권고안(KAIST 발신만 저장, 민감 제목 제외, 90일 삭제)은 쓰지 않는다.
- **구글 토큰 (사용자 결정: 통합):**
  - `kaist google login` 한 번으로 `calendar.app.created`와 `gmail.readonly`를 함께 승인한다. `cal login`은 별칭이다.
  - 사용자는 Google Cloud 콘솔에서 Gmail API를 켜야 한다.
- **S6 연결:**
  - 학사 일정 후보는 과목에 매핑된 메일(제목·본문에 과목 코드나 이름이 있는 것)과 본인에게 직접 온 메일에서만 뽑는다.
  - 학교 전체 메일링 리스트의 "시험" 단어(어학시험, 세미나 등)는 잡음이 많다.
  - 메일 출처는 B등급이다.
