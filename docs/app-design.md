# 프로그램화 설계 (feature/app)

상태: 설계 중 (2026-10-16 시작). 완결 전까지 `feature/app` 브랜치에만 커밋한다. `main`의 CLAUDE.md는 완결 때 고친다.

## 목표 (사용자 요청, 2026-10-16)

- 학교 계정 ID·비밀번호를 입력받아 프로그램이 직접 로그인하고, 2단계 인증(폰 승인)이 필요하면 기다렸다가 이어서 진행한다.
- 이후 자동으로 최신화(sync)하고 드라이브에 저장한다.
- 사용자 본인뿐 아니라 다른 사람도 쉽게 쓸 수 있어야 한다.
- AI는 적당한 오픈소스 모델을 프로그램에 붙여, 프로그램 자체로 동작하게 한다(외부 에이전트 없이).

## 기존 확정 규칙과의 관계

| 규칙 (CLAUDE.md / handoff) | 이번 작업 |
|---|---|
| 비밀번호를 묻거나 저장하거나 자동 입력하지 않는다 | **변경** (결정 1·2) |
| 개인 Windows PC에서만 쓴다 | **변경 예정** (대상·배포 결정 뒤) |
| 2단계 인증을 우회하지 않는다 | 유지. 폰 승인은 사용자가 한다 |
| 읽기만 한다 (제출·글쓰기·설정 변경 없음) | 유지 |
| 받은 자료는 개인 학습용, 공유 기능 없음 | 유지. 각 사용자는 자기 계정·자기 드라이브만 쓴다 |
| 요청 간격·동시 2개 이하, WS 토큰 금지 | 유지 |

## 결정 (2026-10-16)

1. **로그인:** 프로그램이 ID·비밀번호를 받아 실제 로그인 페이지에 채우고, 폰 승인을 기다린다. 2단계 인증은 그대로다.
2. **비밀번호 보관:** 사용자 선택, 기본은 저장하지 않음(그 로그인에만 쓰고 버림). 설정에서 켜면 Windows 사용자 계정에 묶인 자격 증명 저장소에 보관하고, 이후에는 폰 승인만으로 다시 로그인한다.

3. **내장 AI 역할:** 수집 보조(공지에서 일정 추출·분류, 요약 생성) + 질문 응답(로컬 파일을 근거로 "이번 주 할 일", "이 과제 뭔지" 같은 질문에 답하는 대화창). 수식·코드 풀이 같은 고난도 작업은 범위 밖.

4. **프로그램 형태:** Electron 기반 트레이 상주 데스크톱 앱(설치 프로그램). 첫 실행 설정 마법사(계정·구글·드라이브 폴더·AI 모델 다운로드), 로그인 창은 앱 안 창, 자동 sync는 앱이 돌림, 대화창 포함. Playwright는 Electron으로 대체한다.

5. **대상·배포:** KAIST 구성원 중 지인에게 설치 파일 직접 공유(소수). 구글 미인증 앱 100명 한도 안, 코드 서명 없이 안내로 넘어갈 수 있는 규모. 나중에 공개로 넓힐 여지는 둔다.

## 조사 (Opus, 2026-10-16 진행 중)

- 로그인 흐름 구조: 저장된 기록·코드만 분석 (서버 요청 없음)
- 로컬 오픈소스 LLM 후보: 한국어 품질, 라이선스, 런타임, 하드웨어 티어
- 구글 OAuth 배포 제약: 범위 등급, 미인증 앱 한도, 검증 비용
- Electron 이식 제약: 내장 Node 버전과 `node:sqlite`, 네이티브 모듈(LLM 런타임), 앱 안 로그인 창과 쿠키 추출, PDF, 트레이·자동 시작, 설치 프로그램·코드 서명

결과는 `docs/research/`에 옮겨 둔다.

## 위험 (지금까지 파악한 것)

- 다른 사람의 학교 계정 자격 증명을 다루는 책임. 저장은 기본 꺼짐, 켜도 OS 자격 증명 저장소만 쓴다.
- 로그인 시도 빈도와 계정 잠금. 자동 재시도는 1회 이하, 캡차·잠금 화면이면 멈추고 사용자에게 알린다.
- 학교의 자동화 접근 정책. 사용자가 늘면 눈에 띌 수 있다.
- 소형 로컬 모델은 한국어 날짜 추출·요약 품질이 Claude보다 많이 낮다. 기존 검증 규칙(원문 대조·요일·학기 범위, A/B 등급)으로 보완한다.
